# Demo: a synthetic recessive trio (DEMO_TRIO)

This document is a **fully reproducible** end-to-end demo of
PublicGenomicAgent on a synthetic family trio with a recessive
variant. It does not require any real patient data. It runs in
about 30 seconds on a laptop.

It is the reference walkthrough to verify that a fresh install of
the project works correctly, and it is the regression target of
`tests/integration/test_demo_trio.py`.

---

## 1. Clinical context

A consanguineous family presents with an early-onset recessive
phenotype:

- **Proband**: affected, homozygous for a rare variant.
- **Father**: unaffected, heterozygous carrier.
- **Mother**: unaffected, heterozygous carrier.

To keep the demo deterministic and reproducible, we do not use a
real gene. Instead, we generate a small synthetic reference
(`chr1:1-10000`, all `A`) and plant a single SNV at `chr1:1100`
(`A>G`) with Mendelian inheritance:

| Sample | Genotype | Status |
|---|---|---|
| `father` | `0/1` | unaffected carrier |
| `mother` | `0/1` | unaffected carrier |
| `proband` | `1/1` | affected, homozygous |

The analysis region of interest (ROI) is `chr1:1000-1200`,
labelled `DEMO1`.

The expected classification of the variant is **`auto_rec_hom`**
(autosomal recessive, homozygous in the proband).

## 2. Prerequisites

PublicGenomicAgent must be installed with the `pga-core` and
`pga-hts` micromamba environments available. See the
[README](../README.md) or
[`docs/installation.md`](installation.md).

Verify the environments:

```bash
pga env verify
```

You should see `pga-core` and `pga-hts` marked as `ok`.

## 3. Generate the synthetic trio

The script `scripts/make_demo_trio.py` generates all the input
files needed for the analysis:

```bash
python3 scripts/make_demo_trio.py
```

This creates the following files under `results/demo_trio/`:

| File | Description |
|---|---|
| `ref.fa` | Synthetic reference (`chr1:1-10000`, all `A`) |
| `ref.fa.fai` | FASTA index |
| `father.bam` + `.bai` | BAM with the variant at `0/1` |
| `mother.bam` + `.bai` | BAM with the variant at `0/1` |
| `proband.bam` + `.bai` | BAM with the variant at `1/1` |
| `case.json` | The `CaseManifest` for the family |

The BAMs are simulated at 60× coverage with realistic error rates
and base qualities. They are unpaired single-end reads, which is
why the pipeline needs `-B` in `bcftools mpileup` (see
[`docs/known_issues.md`](known_issues.md)).

The script is idempotent: re-running it overwrites the outputs.

## 4. Run the pipeline

The full pipeline is executed by a single command:

```bash
pga run-trio \
    --father results/demo_trio/father.bam \
    --mother results/demo_trio/mother.bam \
    --proband results/demo_trio/proband.bam \
    --reference results/demo_trio/ref.fa \
    --region chr1:1000-1200 \
    --case-id DEMO_TRIO --label DEMO1
```

The `RuleBasedPlanner` decides the sequence of tool calls
automatically based on the state. No user intervention is needed
beyond this single invocation.

## 5. Expected output

The loop runs **11 iterations**:

```
Loop terminado: 11 iteraciones
  ✓ planner:qc_bam → qc_bam
  ✓ planner:qc_bam → qc_bam
  ✓ planner:qc_bam → qc_bam
  ✓ planner:fetch_roi → fetch_roi
  ✓ planner:fetch_roi → fetch_roi
  ✓ planner:fetch_roi → fetch_roi
  ✓ planner:call_variants → call_variants
  ✓ planner:call_variants → call_variants
  ✓ planner:call_variants → call_variants
  ✓ planner:joint_call → joint_call
  ✓ planner:mendelian_filter → mendelian_filter
```

The final state is saved to `results/DEMO_TRIO.session.json`.

The `mendelian_filter` tool classifies the variant as
**autosomal recessive homozygous** and writes four VCFs to
`results/mendelian/`:

- `de_novo.vcf.gz` (empty)
- **`auto_rec_hom.vcf.gz`** (contains the variant)
- `auto_dom.vcf.gz` (empty)
- `x_linked_rec.vcf.gz` (empty)

## 6. Verify the result

Inspect the joint VCF generated by `joint_call`:

```bash
bcftools view -H results/roi/joint_chr1_1000_1200.vcf.gz
```

Expected:

```
chr1  1100  .  A  G  ...  GT:PL:DP:AD
  0/1:...:63:23,40    # father
  0/1:...:63:23,40    # mother
  1/1:...:63:0,63     # proband
```

Inspect the recessive candidates:

```bash
bcftools view -H results/mendelian/auto_rec_hom.vcf.gz
```

The variant `chr1:1100 A>G` must be present with exactly the
genotypes above. If it is, the pipeline has correctly resolved
the case.

## 7. Clinical interpretation

The output VCF is the machine-readable evidence of the case.
The interpretation, in one sentence:

> A rare SNV at `chr1:1100` segregates in the family with an
> autosomal recessive pattern: both parents are healthy
> heterozygous carriers, and the affected proband is homozygous
> for the alternate allele.

In a real clinical setting, the same pattern would be evaluated
against:

- population allele frequencies (gnomAD, local cohorts);
- predicted functional impact (VEP, snpEff, in silico scores);
- the patient's HPO terms via `phenotype_ranking`;
- segregation in additional family members.

The point of this demo is not the biology of the variant (which
is synthetic) but the fact that the agent resolves the
segregation automatically, end-to-end, from a single command.

## 9. Regression test

This entire walkthrough is covered by
`tests/integration/test_demo_trio.py`, which runs the pipeline
in a temporary directory and verifies:

1. The sequence of tool calls is exactly the 11 listed above.
2. `joint_call` produces a VCF with the three samples.
3. The variant `chr1:1100 A>G` has genotypes `0/1`, `0/1`, `1/1`.
4. `mendelian_filter` classifies it as `auto_rec_hom`.
5. The session JSON is serializable and all tool calls succeed.

Run it with:

```bash
pytest tests/integration/test_demo_trio.py -v
```

This test is the regression net for the whole system. Any change
to the planner, the tools, or the pipeline must keep it green.

## 10. Notes

- The pipeline runs **entirely offline**. No data leaves the
  machine. See [`docs/privacy.md`](privacy.md).
- The demo is **reproducible**: the same input files produce the
  same output files, bit for bit.
- The synthetic BAMs are unpaired, which is why the pipeline uses
  `-B` in `bcftools mpileup`. See
  [`docs/known_issues.md`](known_issues.md).
- For a real clinical case, replace `make_demo_trio.py` with your
  own BAMs and a `CaseManifest` from `pga tool case-manifest` or
  a `.fam` file.
